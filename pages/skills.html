Модуль 02 · скиллы

Что такое SKILL.md

Скилл — это файл с инструкциями, который ИИ-ассистент читает и применяет автоматически. Ты пишешь правила один раз, а агент следует им в каждой подходящей задаче.

01 / Идея скилла

Обычно ИИ отвечает «в общем». Скилл задаёт конкретный порядок действий, стиль и ограничения для узкой задачи. Это похоже на памятку для нового сотрудника: коротко, по делу, с примерами.

Задача

Что именно должен делать агент: проверять код, писать тесты, оформлять отчёт.

Порядок

Шаги по номерам. Так результат воспроизводим, а не случаен.

Ограничения

Правила «всегда» и «никогда»: что нельзя делать ни при каких условиях.

02 / Анатомия файла

Вверху — заголовочный блок между линиями --- (front matter) с полями name и description. Дальше — обычный Markdown с инструкциями.

SKILL.md 
---
name: code-review
description: Проверяет код перед слиянием и находит риски.
---

# Проверка кода

## Когда использовать
- Перед слиянием ветки.
- После крупного изменения.

## Инструкции
1. Прочитай изменения целиком.
2. Найди ошибки, дубли и риски безопасности.
3. Предложи правки списком, от важного к мелкому.

## Правила
- Всегда ссылайся на конкретные строки.
- Никогда не переписывай код без объяснения.

Блок между ---. Поле name — короткое имя скилла, description — одна фраза о том, что делает скилл и когда его применять. Ассистент по описанию понимает, когда скилл уместен.

Заголовок задаёт тему. Раздел «Когда использовать» помогает агенту понять контекст: в каких ситуациях доставать этот скилл.

Нумерованные шаги. Пиши глаголами: «прочитай», «найди», «предложи». Чем конкретнее шаг, тем стабильнее результат.

Жёсткие ограничения: «всегда…», «никогда…». Они защищают от типичных ошибок агента — выдумывания данных, лишних изменений, потери контекста.

03 / Как написать свой скилл

  1. Выбери одну узкую задачу

    Скилл должен решать что-то конкретное: «проверить код», «написать тесты», «оформить конспект». Не пытайся описать всё сразу.

  2. Создай файл и заголовочный блок

    Имя файла — SKILL.md. В начале укажи name и description между линиями ---.

  3. Опиши шаги по номерам

    3–6 шагов достаточно. Каждый шаг начинай с глагола действия и не смешивай два действия в одном.

  4. Добавь пример и правила

    Покажи короткий пример «до и после» и перечисли ограничения: что делать всегда и чего не делать никогда.

  5. Проверь и подключи

    Попробуй скилл на реальной задаче, поправь формулировки. Затем подключи его — локально или в общий harness (см. раздел Подключение).

04 / Готовые примеры

Нажми «Копировать», вставь в редактор и адаптируй под свою задачу.

Скилл: конспект урока 
---
name: lesson-notes
description: Превращает текст урока в структурированный конспект.
---

# Конспект урока

## Когда использовать
- Нужно сжать длинный текст до ключевых мыслей.

## Инструкции
1. Определи главную тему одним предложением.
2. Выпиши 3–5 ключевых мыслей списком.
3. Добавь раздел «Термины» с короткими определениями.
4. Закончи блоком «Вопросы для самопроверки».

## Правила
- Не добавляй факты, которых нет в исходном тексте.
- Формулируй коротко: одна мысль — одна строка.
Скилл: проверка тестов 
---
name: test-review
description: Проверяет, что тесты покрывают основные случаи.
---

# Проверка тестов

## Когда использовать
- После написания новых тестов.

## Инструкции
1. Перечисли, какие случаи уже покрыты.
2. Найди непокрытые граничные случаи.
3. Предложи конкретные новые проверки.
4. Отметь тесты, которые проверяют не то, что заявлено.

## Правила
- Всегда указывай, какой случай остался без теста.
- Никогда не удаляй тесты без явной причины.

Совет. Начни с шаблона «SKILL.md» в редакторе — он уже содержит правильную структуру. Просто заполни разделы под свою задачу.
